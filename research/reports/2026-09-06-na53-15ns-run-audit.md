# NA53 Run Audit — the completed production run is 15 ns, not 100 ns (2026-09-06)

**Why this report exists:** the raw archive for the run that finished `2026-09-06 08:45:37 CST`
(job `na53_prod 2036720`, node `cpn3133`, Taiwania-3 `ct56`) was downloaded to the workstation and
verified against its own `prod.log` / `.tpr`. That verification **corrects the record**: the run that
was reported as "100 ns production" in `2026-09-06-na53-15ns-results-superseded.md` is actually a **15 ns**
production run. Several secondary numbers in that report are also corrected here (energy term
extraction, Rg column, cluster interpretation). All corrections were recomputed from the raw
`.xvg` files in `archive/2026-09-06_15ns_prod/` (now mirrored at
`/run/media/cliff/WD_HDD/GROMACS/NA53_15ns_results/15ns_prod/`).

---

## 1. Primary correction: the run length is 15 ns

| Evidence | Value |
|---|---|
| `prod.log` header | `nsteps = 7500000` (7,500,000 steps) |
| `prod.log` last energy row | `7500000  15000.00000` (time = 15,000 ps) |
| `.tpr` (via SLURM err capture) | `starting mdrun 'Protein in water' 7500000 steps, 15000.0 ps.` |
| mdrun `Performance:` | `18.315 ns/day · 1.310 h/ns`, wall 70,760.9 s (19 h 39 m) ⇒ 15.0 ns produced |
| All trajectory `.xvg` | 1,501 frames, time 0 → 15,000 ps (10 ps/frame) |
| Repo `configs/prod.mdp` | `nsteps = 250000000` (500 ns) — **not** what ran; the sbatch temp-mdp override set 7.5 M |

**Why:** the generated job that ran carried `NS_LENGTH="${1:-15}"` (the 15 ns pilot default of the
launcher/template version in use on Taiwania 3 at submission, Sep 5 11:45). The report's claim of a
`--ns 100` submission is not supported by the run artifacts. The current repo template defaults to
`NS_LENGTH="${1:-100}"` with `PROD_NS=100` (`slurm/03_prod.sbatch`, `profiles/taiwania3_cpu.env`),
so *future* submissions are not affected — but **always verify** after submitting:
`grep NS_LENGTH slurm/jobs/03_prod_*.sbatch` and, once mdrun starts, the
`… steps, … ps` line in the prod log.

**Throughput implications (redo of the ETA math):**
- Measured production rate: **18.315 ns/day** (1.31 h/ns) — this is real and unchanged.
- **100 ns therefore needs ≈ 131 h of production wall**, which **does not fit** one `ct56` job
  (`--time=95:00:00`). The earlier statement "100 ns now fits a single 95 h slot" was an artifact
  of dividing the 15 ns wall time by 100. A genuine 100 ns run needs **two sequential 95 h jobs**
  via the checkpoint restart path (≈ 72 + 28 ns), i.e. ~6 days wall including prep, exactly as the
  pre-run ETA table in `2026-09-05-na53-t3-first-production-results.md` §5 predicted (59 + 41 ns
  segments).

## 2. Secondary corrections (from raw files)

### 2.1 Energy-term extraction was wrong in three places — fixed and re-extracted
Same bug class as the earlier Pressure incident (`docs/INCIDENT_ANALYSIS.md`, V-class):
`gmx energy` term IDs are **per-.edr and shift when the run writes different term sets**.

| File in archive | Was extracted with | Actually contained | Corrected to (term) |
|---|---|---|---|
| `energy_Density.xvg` (prod) | term 36 | **Pres-XY** (bar, oscillating ≈ 0) | **23 Density** → mean **988.6 kg/m³** |
| `nvt_temperature.xvg` | term 15 | **Conserved-En** (−4.09e6 kJ/mol) | **16 Temperature** (nvt.edr has `Position-Rest.` → shift) → mean **310.2 K** |
| `em_potential.xvg` | term 10 | **Coul.-recip.** (+3.7e5) | **11 Potential** (em.edr) → final **−4.86e6 kJ/mol** |
| `npt2_density.xvg` | term 24 | **pV** | **23 Density** → mean 988.7 kg/m³ |
| `npt2_pressure.xvg` | term 23 | **Density** | **17 Pressure** → mean 2.7 bar |
| prod `energy_Pressure/Temperature/Potential/Conserved-En` | 17/15/11/14 | correct | unchanged (verified) |

Corrected `.xvg` re-extracted from the live `.edr` files on Taiwania 3 and written back to the
archive (both T3 `archive/2026-09-06_15ns_prod/` and the local mirror). The root cause is fixed in
the repo: new `scripts/gmx_energy_lib.sh` looks every term up **by name** from each `.edr`'s own
list; `02_equilibration.sh` and `04_analysis.sh` now use it (commits `7841d56`, `8932876`).

### 2.2 Radius of gyration: report read the wrong column
`gyrate.xvg` columns are `s0 Rg` (true total), then `s1 Rg/sX/N`, `s2 Rg/sY/N`, `s3 Rg/sZ/N`.
The reported Rg (mean 2.9395 nm, sd 0.218) matches **no** column. True total Rg (`s0`, recomputed
over all 1,501 frames):
**mean 3.548 nm · sd 0.104 · range 3.265–3.861 · final 3.460 nm.**
This is a *moderately extended/elongated* globule (not the tighter 2.9 nm picture), breathing
±0.1 nm — still far from the ~14 nm fully extended chain.

### 2.3 Cluster analysis contradicts "a single dominant conformational family"
`cluster.log` (gromos, RMSD cutoff 0.2 nm, 1,501 frames): **347 clusters**; largest cluster = 11
frames (**0.7 %**); top-5 = 3.7 %; top-10 = 7.1 %; 73 one-frame singletons. There is **no dominant
conformational family**. Frames drift continuously through distinct structures — fully consistent
with the non-converging RMSD. The §6 sentence in the 100 ns report is wrong and is retracted.

### 2.4 Conserved-En drift is an artifact of the thermostat, not a defect
Conserved-En climbs +205,000 kJ/mol over the run (+13,700 kJ/mol/ns). Under the v-rescale
thermostat the "conserved" quantity is **not** conserved by design. The real health markers are
stable: Temperature 310.14 ± 0.59 K with drift −0.003 K/ns, Potential −4.090e6 ± 2,358 kJ/mol
(±0.06 %), Density 988.6 ± 1.6 kg/m³. No heating, no drift pathology.

## 4. What this means for the project

1. The pilot run is a **valid 15 ns production dataset** — useful for methods/throughput validation
   and preliminary conformational sampling — but it is **not** a converged 100 ns trajectory and
   must not be labeled or cited as one.
2. A genuine 100 ns run at 18.3 ns/day needs **two sequential 95 h ct56 jobs** via the checkpoint
   restart path (≈ 72 + 28 ns, ~6 days wall) — or a GPU partition for a step change in rate.
3. Replica/extended sampling is still the open decision (see §10 of the 100 ns report and
   `docs/CLUSTER_RUNBOOK.md`): with no dominant cluster even at 15 ns, single-trajectory conclusions
   about the aptamer fold are provisional.
4. Analysis-code defense-in-depth: name-based energy-term lookup is now in place; add
   post-extraction unit sanity checks (density ≈ 1,000 kg/m³, pressure mean ≈ 1 bar, T ≈ 310 K) to
   `04_analysis.sh` / `02_equilibration.sh` as a future guard (recommended follow-up).
